TWO ROWS THAT PASS FOR A NARROWER REASON THAN THEY APPEAR TO
------------------------------------------------------------

lockfile-committed — reads "package.json has no dependencies".

  That is TRUE OF THE ROOT package.json ONLY, which is the one this check looks
  at, and it is not where this app's packages are. Every package the app runs is
  in web/package.json: Next.js, React, @supabase/ssr, @supabase/supabase-js,
  @sentry/nextjs.

  web/package-lock.json IS tracked in git, and `npm ci` in CI's "App build" job
  is what proves it: npm ci fails outright if the lockfile is missing or out of
  step with package.json. So the thing the row is for is established — by a
  different check than the one reporting PASS.

  The same shape of gap was real in .github/dependabot.yml until 15 October: its
  npm entry pointed at the root too, so Dependabot watched a manifest with no
  dependencies. PR #316 added `directory: "/web"`.

repo-private — reads "N/A - public by decision".

  This repository is public on purpose: Vercel's Hobby plan cannot deploy a
  private repository owned by a GitHub organisation. docs/decisions/public-repo.md
  is the record, and evidence/repo-private.md is the row's answer.

  The row was an AUTOMATIC check until 15 October. It is now an evidence row,
  because launch-check.mjs's repo_private hard-codes PUBLIC to FAIL and the
  script has no N/A path for an auto row — so a repository public by a recorded
  decision could not be recorded as anything but a failure. The cost is stated
  rather than hidden: NOTHING NOW WATCHES THE REPOSITORY'S VISIBILITY.
